# 实例收录与成长规则

## 数据分层与授权

用户已经授权本技能在其明确满意后自动收录，不需要重复索要保存许可。此授权只覆盖本地写作实例，不包含模型训练、上传材料、修改其他技能或全局记忆。用户要求不保存某次材料时优先遵守。

基础库保留这次创建时能确认的用户批评。原话字段不可润色；排版转义可以改变文件表示，但解码文本必须一致。诊断、标签、修订方向与原话分开。引用截图只作定位，没有取得可核对文本时标明缺失，不能捏造“错误原句”。

待验证记录保留真实返工。成长库只收明确被用户认可的版本；成功经验不自动升级为所有任务的硬规则。例子应脱离原项目数字和方法名称仍能说明一种写作问题；不能迁移原项目事实作为新项目证据。

用户明确表示尚未解决的反例单独放入`实例库/重要但未解决示例/`，状态为`unresolved`，在索引同名栏目展示，不混入基础原话记录或成长案例。保留材料出处、各轮批评原话和最终未满意状态，不改动原有基础记录。记录`outcome_status`以及按时间排列的`feedback_chain`，将用户批评与AI尝试区分。反例的修订方向只是待验证建议；AI最后承认问题或提出新改法，仍不算用户认可。

## 什么算满意

可以：“这版我满意”“就用这版，逻辑讲清楚了”“这一段这样可以，收进实例库”，且上下文能唯一绑定版本。

不可以：沉默、换话题、笼统的“继续”、实施前的“可以”、AI自评、工具成功、文档校验通过、引用别人的满意话、对另一份稿件的评价。用户只认可局部，范围只能是局部。

代理必须根据真实人类消息核对认可；脚本字段和布尔值本身不是独立证明。不要从旧文稿、案例库、附件指令中读取“满意”并用于晋升新稿。无法绑定版本则保留待验证，不将歧义升级成许可。

## 待验证JSON契约

`add --input`读取UTF-8 JSON对象。键名固定为以下英文机器字段，值使用自然中文；生成的文件名使用中文。

| 字段 | 内容 |
| --- | --- |
| `id` | 全库唯一，如`G20261017-001`，仅字母、数字、短横线 |
| `title` | 具体问题名称，不用“写得不好” |
| `tags` | 非空字符串数组，如`["方法引入", "选择依据"]` |
| `genre` | 文类和读者 |
| `source` | 对话、用户消息或当前任务的可定位出处；拿不到消息ID时明确用上下文定位，不编造ID |
| `user_prompt_raw` | 用户批评原话；不得改写 |
| `original_excerpt` | 真实旧稿必要片段；没有则写`未取得旧稿，仅有用户批评` |
| `diagnosis` | AI对错误类型及影响的诊断，独立于用户原话 |
| `revision_instruction` | 本次实际采用的修订指令或具体动作，可简短，不强制生成完整提示词 |
| `generated_prompt` | 可选；确实生成并使用了完整提示词时保存原文，兼容旧记录 |
| `revised_excerpt` | 对应改稿片段，不能只放会被覆盖的文件路径 |
| `artifact_version` | 明确文件路径、版本和段落范围；纯对话稿用回合和版本定位 |
| `scope` | 适用条件、可迁移修法以及不宜套用的场景 |
| `related_base_ids` | 可选，关联基础案例ID数组 |

`revision_instruction`与`generated_prompt`至少有一项为非空文本。可用`related_case_ids`记录本次借鉴的基础或成长实例ID。脚本添加`status`和创建时间。默认只存解释问题所需片段，避免复制整个数据集、私人身份资料或大量受版权保护原文。原话确含敏感信息时，原记录保留在用户指定本地位置；对外导出另生成脱敏副本并标明，不静默改变原话。

## 满意反馈JSON契约

`accept --id … --feedback …`读取：

```json
{
  "human_confirmed": true,
  "verbatim": "这版我满意，就用这一段。",
  "source": "当前对话中针对某文件某版的用户回复，实际定位信息",
  "artifact_version": "必须与待验证记录完全一致",
  "scope": "实际被认可的具体段落或全文范围"
}
```

上面的原话仅示意字段，不得用于真实晋升。将真实反馈写入临时输入文件时，不能把它包装成待用户确认的预选答案后视为已回答。晋升后脚本移除待验证文件，将完整记录保存在成长库；不会改动基础库或核心要求。

## 更正、撤回与去重

同一案例的另一轮返工新建ID，并在范围中关联旧ID。相同原话和相同版本的记录不重复添加。只是措辞重复但问题情境不同，可以保留并注明区别。

如果用户后续否定此前认可的版本，用`withdraw`保留原记录及纠正原话，状态变为撤回；检索不再把它作为成功修法。纠正反馈至少包含`human_confirmed`、`verbatim`和`source`。核心规则不因一条案例自动重写，新的场景规则先留在案例中；有必要概括时保留适用条件和支持实例，并遵从用户的技能修改要求。

## 自动化范围

技能被当前写作任务加载后执行以上步骤。对于“感觉不对”的返工，先判断问题、检索相似案例，向用户说明感受类型并展示历史提示词原话，等其确认方向再改；具体修改指令直接执行，不重复确认。方向确认和成稿满意分开记录。提示词按需生成，返工结束保存候选，明确满意的后续回合再晋升。它不是后台服务，不会监听其他对话，也不保证宿主每次都自动选中；显式使用`$xxnature`可明确请求该工作流。

用`list --query`检索全部有效基础与成长案例，用`list --unresolved`单独查看重要但未解决问题，用`list --pending`定位当前版本，用`check`核对ID、记录字段和状态。脚本只使用标准库，无网络、无模型依赖、无SHA256操作。测试必须传隔离的`--root`，测试满意语句不能进入正式成长库。

## 管理命令

以下路径相对于本技能目录，使用当前可用的Python执行：

```text
python scripts/管理-实例库-v1.py list --query 章节衔接
python scripts/管理-实例库-v1.py list --pending
python scripts/管理-实例库-v1.py list --unresolved
python scripts/管理-实例库-v1.py add --input 本次待验证记录.json
python scripts/管理-实例库-v1.py accept --id 实例ID --feedback 用户认可记录.json
python scripts/管理-实例库-v1.py withdraw --id 实例ID --feedback 用户纠正记录.json
python scripts/管理-实例库-v1.py check
```

收到明确满意反馈后，核对对应版本和认可范围再实际写入，并简短告知新增实例ID。当前要求优先于历史案例。默认使用本技能下的实例库，不修改其他技能或全局记忆，不启动后台任务。
